# Block 5b — the gate migration audit

Every `check(...)` call site in the nine `gate_block*.py` scripts of the Step-3 rebuild, and where it went. The scripts
lived in a session scratchpad and were **deleted** at the end of Block 5b; this table is the record that each of their
checks was either migrated into `tests/` or dropped for a stated reason.

Read it as the answer to "was anything lost when the gates went away?".

* **`<file>_test.py::<test>`** — migrated. The test exists in the mirror; the audit script resolved every name here
  against `tests/` by AST, so a typo or a later rename fails the audit rather than passing silently.
* **`DROP: …`** — not migrated, with the reason. Where the reason names a mirror test, that name is resolved too, so
  "already covered by 5a" is a checkable claim.

`kind` is `runs` where the check executes code and `source` where it parses source text (AST / `tokenize`). The
`source` group are **merge guards** — they assert that code removed in the three-branch merge stayed removed — and are
carried in the suite under `@pytest.mark.source_invariant` so they can be retired together once the rebuild is
history. See `rebuild-plan.md`.

`/f-str` marks a site whose label was an f-string, so the `condition` and `loop over` columns carry the context the
label cannot.
